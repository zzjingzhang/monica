# 联系人详情页驱动机制分析

## 一、核心架构概述

联系人详情页的渲染由**四层驱动架构**共同驱动：

```
Account（账户）
    ↓
Template（账户模板）
    ↓
TemplatePage（模板页面）
    ↓
Module（模块） → Module::TYPE_*（模块类型）
```

各层的核心职责：

- **Account**：数据隔离的顶层边界，所有模板、页面、模块都归属于特定账户
- **Template**：联系人展示结构的容器，一个账户可以有多个模板，每个联系人绑定一个模板
- **TemplatePage**：模板下的页面，按 position 排序展示
- **Module**：页面的功能单元，按模块类型决定数据装配逻辑

核心模型关系：

| 模型 | 关键关系 |
|------|---------|
| [Template.php](file:///Users/zhangjing/Desktop/so-coders/0508-und-p/monica/app/Models/Template.php) | belongsTo Account, hasMany TemplatePage, hasMany Contact |
| [TemplatePage.php](file:///Users/zhangjing/Desktop/so-coders/0508-und-p/monica/app/Models/TemplatePage.php) | belongsTo Template, belongsToMany Module (via module_template_page) |
| [Module.php](file:///Users/zhangjing/Desktop/so-coders/0508-und-p/monica/app/Models/Module.php) | belongsTo Account, belongsToMany TemplatePage |

### 2.3 关联模块到页面 (AssociateModuleToTemplatePage)

服务类：[AssociateModuleToTemplatePage.php](file:///Users/zhangjing/Desktop/so-coders/0508-und-p/monica/app/Domains/Settings/ManageTemplates/Services/AssociateModuleToTemplatePage.php)

**执行流程**：

1. 权限校验（同 CreateTemplate

2. **三层归属校验**（关键安全机制）：

```php
// 1. 校验模块属于当前账户
$this->module = $this->account()->modules()
    ->findOrFail($this->data['module_id']);

// 2. 校验模板属于当前账户
$template = $this->account()->templates()
    ->findOrFail($this->data['template_id']);

// 3. 校验页面属于该模板
$this->templatePage = $template->pages()
    ->findOrFail($this->data['template_page_id']);
```

3. 计算模块在页面中的位置：

```php
$newPosition = $this->templatePage->modules()->max('position') + 1;
```

4. 建立关联（带位置信息）：

```php
$this->templatePage->modules()->syncWithoutDetaching([
    $this->module->id => ['position' => $newPosition],
]);
```

### 2.4 调整页面顺序 (UpdateTemplatePagePosition)

服务类：[UpdateTemplatePagePosition.php](file:///Users/zhangjing/Desktop/so-coders/0508-und-p/monica/app/Domains/Settings/ManageTemplates/Services/UpdateTemplatePagePosition.php)

**执行流程**：

1. 权限校验（同 CreateTemplate

2. 归属校验（模板和页面都必须属于当前账户

3. 根据移动方向（升序/降序）调整相邻页面的 position：

```php
private function updatePosition(): void
{
    if ($this->data['new_position'] > $this->pastPosition) {
        $this->updateAscendingPosition();
    } else {
        $this->updateDescendingPosition();
    }

    $this->templatePage->update(['position' => $this->data['new_position']);
}
```

- **升序调整**（向后移动）：将原位置和新位置之间的页面 position 减 1

```php
$this->template->pages()
    ->where('position', '>', $this->pastPosition)
    ->where('position', '<=', $this->data['new_position'])
    ->decrement('position');
```

- **降序调整**（向前移动）：将新位置和原位置之间的页面 position 加 1

```php
$this->template->pages()
    ->where('position', '>=', $this->data['new_position'])
    ->where('position', '<', $this->pastPosition)
    ->increment('position');
```

## 四、ContactPageController 通过 slug 查找模板页面

控制器类：[ContactPageController.php](file:///Users/zhangjing/Desktop/so-coders/0508-und-p/monica/app/Domains/Contact/ManageContact/Web/Controllers/ContactPageController.php)

### 4.1 查找逻辑

```php
public function show(Request $request, string $vaultId, string $contactId, string $slug)
{
    $vault = Vault::findOrFail($vaultId);
    $contact = Contact::with([...])->findOrFail($contactId);

    // 如果联系人没有绑定模板，重定向到空白页
    if (! $contact->template_id) {
        return redirect()->route('contact.blank', [...]);
    }

    // 核心查找：通过 slug + template_id 双重条件定位页面
    $templatePage = TemplatePage::where('slug', $slug)
        ->where('template_id', $contact->template_id)
        ->firstOrFail();

    // 更新联系人浏览记录
    (new UpdateContactView)->execute([...]);

    return Inertia::render('Vault/Contact/Show', [
        'layoutData' => VaultIndexViewHelper::layoutData($vault),
        'data' => ContactShowViewHelper::dataForTemplatePage($contact, Auth::user(), $templatePage),
    ]);
}
```

### 4.2 关键要点

1. **双重条件查找**：同时使用 `slug` 和 `template_id` 确保页面属于正确的模板上下文

2. **防越权**：即使不同模板下有相同 slug 的页面，由于 `template_id` 来自当前联系人的模板，也不会错

3. **无模板降级**：联系人未绑定模板时重定向到 `contact.blank`

### 5.3 AssociateModuleToTemplatePage 三层防护

在 [AssociateModuleToTemplatePage.php](file:///Users/zhangjing/Desktop/so-coders/0508-und-p/monica/app/Domains/Settings/ManageTemplates/Services/AssociateModuleToTemplatePage.php#L60-L72) 中的 validate() 方法：

```php
private function validate(): void
{
    $this->validateRules($this->data);

    // 第一层防护：模块必须属于当前账户
    $this->module = $this->account()->modules()
        ->findOrFail($this->data['module_id']);

    // 第二层防护：模板必须属于当前账户
    $template = $this->account()->templates()
        ->findOrFail($this->data['template_id']);

    // 第三层防护：页面必须属于该模板
    $this->templatePage = $template->pages()
        ->findOrFail($this->data['template_page_id']);
}
```

### 5.4 异常抛出机制

如果某层校验失败，Laravel 的 `findOrFail()` 会抛出 `ModelNotFoundException`，从而阻止跨账户关联。

**攻击场景示例**：

假设账户 A 的模块 ID=100，尝试关联到账户 B 的模板页面 ID=200：

1. 当执行 `$this->account()->modules()->findOrFail(100)` 时，由于 `account()->modules()` 只包含账户 A 的模块，如果当前是账户 B 的上下文，查询会抛出 `ModelNotFoundException`，关联操作终止。

## 六、完整调用链路总结

```
设置页操作流 → 服务层校验 → 数据持久化 → 联系人详情页渲染

1. 设置页创建模板：
   CreateTemplate → 权限校验 → 创建 Template → 创建默认 TemplatePage

2. 设置页创建页面：
   CreateTemplatePage → 权限校验 → 归属校验 → 计算 position → 生成 slug → 创建 TemplatePage

3. 设置页关联模块：
   AssociateModuleToTemplatePage → 权限校验 → 三层归属校验 → 建立多对多关联

4. 联系人详情页渲染：
   ContactPageController::show → 按 slug+template_id 查找页面 → ContactShowViewHelper → 按 Module::TYPE_* 匹配 ViewHelper → 渲染各模块数据
```
