# 第三方登录认证链路分析

## 概述

本文档详细分析 Monica 项目中从 `auth/{driver}` 到 callback 完成的完整第三方登录认证链路。

---

## 一、整体流程概览

```
用户点击登录按钮
    ↓
GET /auth/{driver} → [SocialiteCallbackController::login]
    ↓
Provider白名单校验 → checkProvider()
    ↓
重定向到第三方授权页面
    ↓
用户授权后回调
    ↓
GET/POST /auth/{driver}/callback → [SocialiteCallbackController::callback]
    ↓
Provider白名单校验 → checkProvider()
    ↓
错误检查 → checkForErrors()
    ↓
登录Pipeline执行
    ├─ AttemptToAuthenticateSocialite (核心认证逻辑)
    └─ PrepareAuthenticatedSession (会话准备)
    ↓
认证成功 → 跳转首页
```

private function checkProvider(string $driver): void

### 3. UserToken 绑定策略

**UserToken 模型**：[UserToken.php](file:///Users/zhangjing/Desktop/so-coders/0508-und-p/monica/app/Models/UserToken.php)

**核心字段**：
- `driver` - 第三方提供商名称（如 google, github）
- `driver_id` - 第三方返回的唯一用户 ID
- `user_id` - 关联的本地用户 ID
- `email` - 第三方返回的邮箱
- `format` - oauth1 / oauth2
- `token`, `refresh_token`, `token_secret`, `expires_in` - 令牌相关

**绑定逻辑**（[authenticateUser](file:///Users/zhangjing/Desktop/so-coders/0508-und-p/monica/app/Actions/AttemptToAuthenticateSocialite.php#L78-L97) 方法）：

```php
private function authenticateUser(Request $request, string $driver, SocialiteUser $socialite): User
{
    if ($userToken = UserToken::firstWhere([
        'driver_id' => $socialite->getId(),
        'driver' => $driver,
    ])) {
        // 情况1：该第三方账号已绑定过本地用户
        $user = $userToken->user;
        $this->checkUserAssociation($request, $user, $driver);
    } else {
        // 情况2：新绑定 - 创建用户或添加到已登录用户
        $user = tap($this->getUserOrCreate($socialite), function ($user) use ($driver, $socialite) {
            $this->createUserToken($user, $driver, $socialite);
        });
    }
    return $user;
}
```

**绑定策略总结**：
1. **已绑定**：通过 `driver + driver_id` 查找，直接返回关联用户
2. **未绑定但已登录**：将新的第三方账号绑定到当前登录用户
3. **未绑定且未登录**：创建新用户并绑定

### 4. 已登录用户绑定不同账号时的拒绝条件

**位置**：[AttemptToAuthenticateSocialite.php](file:///Users/zhangjing/Desktop/so-coders/0508-und-p/monica/app/Actions/AttemptToAuthenticateSocialite.php#L102-L107)

```php
private function checkUserAssociation(Request $request, User $user, string $driver): void
{
    if (($userId = Auth::id()) && $userId !== $user->id) {
        $this->throwFailedAuthenticationException(
            $request, 
            $driver, 
            trans('This provider is already associated with another account')
        );
    }
}
```

**拒绝条件**：
- 当前存在已登录用户（`Auth::id()` 不为空）
- 且第三方账号已绑定的用户 ID ≠ 当前登录用户 ID

**拒绝效果**：
- 抛出 `ValidationException`，错误信息："This provider is already associated with another account"
- 触发 `Failed` 事件
- 增加登录速率限制计数

### 5. 新用户创建路径

**入口**：[getUserOrCreate](file:///Users/zhangjing/Desktop/so-coders/0508-und-p/monica/app/Actions/AttemptToAuthenticateSocialite.php#L112-L119)

```php
private function getUserOrCreate(SocialiteUser $socialite): User
{
    if ($user = Auth::user()) {
        return $user;  // 已登录，直接使用当前用户
    }
    return $this->createUser($socialite);  // 未登录，创建新用户
}
```

**创建流程**：[createUser](file:///Users/zhangjing/Desktop/so-coders/0508-und-p/monica/app/Actions/AttemptToAuthenticateSocialite.php#L124-L135)

```php
private function createUser(SocialiteUser $socialite): User
{
    $names = Str::of($socialite->getName())->split('/ /', 2);
    $data = [
        'email' => $socialite->getEmail(),
        'first_name' => $names[0],
        'last_name' => $names[1] ?? $names[0],
        'terms' => true,
    ];

    return tap(app(CreateNewUser::class)->create($data), fn (User $user) => event(new Registered($user)));
}
```

**CreateNewUser 内部流程**：[CreateNewUser.php](file:///Users/zhangjing/Desktop/so-coders/0508-und-p/monica/app/Actions/Fortify/CreateNewUser.php)
1. 验证输入数据（邮箱唯一性、姓名等）
2. 调用 `CreateAccount` 服务创建完整账户（包含 Account、Vault 等）
3. 触发 `Registered` 事件

**关键点**：
- 新用户**没有密码**（`password` 字段为 `null`）
- 姓名拆分策略：按空格切分，不足两部分时 first_name = last_name
- `terms` 自动设为 `true`（跳过用户手动同意条款）

### 6. 两步验证 / WebAuthn 为什么不会直接登录成功

**位置**：[AttemptToAuthenticateSocialite.php](file:///Users/zhangjing/Desktop/so-coders/0508-und-p/monica/app/Actions/AttemptToAuthenticateSocialite.php#L51-L54)

```php
if ((optional($user)->two_factor_secret && ! is_null(optional($user)->two_factor_confirmed_at))
    || Webauthn::enabled($user)) {
    return $this->twoFactorChallengeResponse($request, $user);
}

$this->guard->login($user, $request->session()->pull('login.remember', false));
```

**判断条件**：

| 条件 | 说明 |
|------|------|
| `two_factor_secret && two_factor_confirmed_at` | 用户已启用并确认了 TOTP 两步验证 |
| `Webauthn::enabled($user)` | 用户已启用 WebAuthn 硬件密钥认证 |

**触发后的处理**：[twoFactorChallengeResponse](file:///Users/zhangjing/Desktop/so-coders/0508-und-p/monica/app/Actions/AttemptToAuthenticateSocialite.php#L195-L207)

```php
protected function twoFactorChallengeResponse(Request $request, ?User $user): Response
{
    $request->session()->put([
        'login.id' => $user->getKey(),
        'login.remember' => $request->session()->pull('login.remember', $request->filled('remember')),
    ]);

    TwoFactorAuthenticationChallenged::dispatch($user);

    return $request->wantsJson()
                ? response()->json(['two_factor' => true])
                : redirect()->route('two-factor.login');
}
```

**为什么不直接登录**：
1. **安全原则**：两步验证的本质是"你知道的" + "你拥有的"双重认证。第三方登录只验证了"你拥有"（第三方账号），但本地的两步验证是独立的第二层保护。
2. **认证分层**：第三方认证解决"身份确认"，本地两步验证解决"登录授权"，两者是独立的安全层。
3. **会话机制**：先将用户 ID 存入 session（`login.id`），然后跳转到两步验证页面，验证通过后才真正完成登录。
4. **事件驱动**：触发 `TwoFactorAuthenticationChallenged` 事件，允许其他逻辑介入。

**User 模型支持**：[User.php](file:///Users/zhangjing/Desktop/so-coders/0508-und-p/monica/app/Models/User.php#L21-L28)
```php
class User extends Authenticatable implements HasLocalePreference, MustVerifyEmail
{
    use TwoFactorAuthenticatable;  // 两步验证
    use WebauthnAuthenticatable;   // WebAuthn
}
```

## 三、防账号串绑保护点分析

### 保护点 1：Provider 白名单校验（基础防线）
- **位置**：[SocialiteCallbackController.php](file:///Users/zhangjing/Desktop/so-coders/0508-und-p/monica/app/Http/Controllers/Auth/SocialiteCallbackController.php#L83-L90)
- **保护作用**：防止使用未授权的认证源

### 保护点 2：错误参数检查
- **位置**：[checkForErrors](file:///Users/zhangjing/Desktop/so-coders/0508-und-p/monica/app/Http/Controllers/Auth/SocialiteCallbackController.php#L71-L78)
- **保护作用**：处理第三方返回的错误，避免继续执行

### 保护点 3：登录速率限制
- **路由中间件**：`throttle:oauth2-socialite`（[web.php](file:///Users/zhangjing/Desktop/so-coders/0508-und-p/monica/routes/web.php#L168)）
- **失败时**：`$this->limiter->increment($request)`（第 175 行）
- **保护作用**：防止暴力破解和重放攻击

### ✅ **最关键的防账号串绑保护点**

**位置**：[checkUserAssociation](file:///Users/zhangjing/Desktop/so-coders/0508-und-p/monica/app/Actions/AttemptToAuthenticateSocialite.php#L102-L107)

```php
private function checkUserAssociation(Request $request, User $user, string $driver): void
{
    if (($userId = Auth::id()) && $userId !== $user->id) {
        $this->throwFailedAuthenticationException(
            $request, 
            $driver, 
            trans('This provider is already associated with another account')
        );
    }
}
```

**为什么这是最关键的保护点**：

**攻击场景**：
1. 攻击者先登录自己的账号 A
2. 然后用受害者已绑定的第三方账号 B 发起 OAuth 登录
3. 如果没有这个检查，系统可能会将 B 绑定到 A，或者直接让 A 登录为 B 的用户

**保护逻辑**：
- 当检测到"当前已登录用户 ≠ 第三方账号已绑定用户"时，直接拒绝
- 这防止了"会话固定攻击"和"账号劫持"
- 确保一个第三方账号只能被其原始绑定的用户使用，不能被其他已登录用户"抢占"

**二次防护**：
- 查找 UserToken 时使用 `driver + driver_id` 复合条件，确保唯一性
- 新绑定时，如果用户已登录，则绑定到当前用户；否则创建新用户

## 五、安全设计总结

| 安全机制 | 实现位置 | 目的 |
|---------|---------|------|
| Provider 白名单 | [checkProvider](file:///Users/zhangjing/Desktop/so-coders/0508-und-p/monica/app/Http/Controllers/Auth/SocialiteCallbackController.php#L83-L90) | 限制可信任的认证源 |
| 账号绑定校验 | [checkUserAssociation](file:///Users/zhangjing/Desktop/so-coders/0508-und-p/monica/app/Actions/AttemptToAuthenticateSocialite.php#L102-L107) | 防止账号串绑和会话劫持 |
