## 1. 文件上传流程

系统支持三种类型的文件上传：文档、照片和头像，分别由三个控制器处理。

### 1.1 文档上传 - ContactModuleDocumentController

[ContactModuleDocumentController.php](file:///Users/zhangjing/Desktop/so-coders/0508-und-p/monica/app/Domains/Contact/ManageDocuments/Web/Controllers/ContactModuleDocumentController.php)

**`store()` 方法 (L16-L40)**：

```php
public function store(Request $request, string $vaultId, string $contactId)
{
    $data = [
        'account_id' => Auth::user()->account_id,
        'author_id' => Auth::id(),
        'vault_id' => $vaultId,
        'uuid' => $request->input('uuid'),
        'name' => $request->input('name'),
        'original_url' => $request->input('original_url'),
        'cdn_url' => $request->input('cdn_url'),
        'mime_type' => $request->input('mime_type'),
        'size' => $request->input('size'),
        'type' => File::TYPE_DOCUMENT,
    ];

    $file = (new UploadFile)->execute($data);

    $contact = Contact::where('vault_id', $vaultId)->findOrFail($contactId);
    $contact->files()->save($file);

    return response()->json([
        'data' => ModuleDocumentsViewHelper::dto($file, $contact),
    ], 201);
}
```

**关键流程**：
1. 从请求中获取Uploadcare返回的文件元数据（uuid、url、mime类型、大小等）
2. 设置文件类型为 `File::TYPE_DOCUMENT`
3. 调用 `UploadFile` 服务创建File模型记录
4. 通过多态关联 `$contact->files()->save($file)` 将文件与联系人关联
5. 返回格式化后的文件DTO

## 3. StorageHelper 存储辅助

[StorageHelper.php](file:///Users/zhangjing/Desktop/so-coders/0508-und-p/monica/app/Helpers/StorageHelper.php)

### 3.1 存储限制计算

**`canUploadFile()` 方法 (L15-L31)**：

```php
public static function canUploadFile(Account $account): bool
{
    // 存储限制为0表示无限制
    if ($account->storage_limit_in_mb == 0) {
        return true;
    }
    
    // 获取账户下所有vault的ID
    $vaultIds = $account->vaults()->select('id')->get()->toArray();
    
    // 计算所有文件的总大小（字节）
    $totalSizeInBytes = File::whereIn('vault_id', $vaultIds)->sum('size');
    
    // 转换账户限制为字节进行比较
    $accountLimit = $account->storage_limit_in_mb * 1024 * 1024;
    
    return $totalSizeInBytes < $accountLimit;
}
```

**计算逻辑**：
1. 检查账户的 `storage_limit_in_mb`，为0表示无限存储
2. 汇总账户下所有vault的所有File记录的 `size` 字段
3. 将账户限制（MB）转换为字节后与总使用量比较

### 3.2 Uploadcare签名生成

**`uploadcare()` 方法 (L36-L45)**：

```php
public static function uploadcare(): array
{
    $signature = config('services.uploadcare.private_key') != '' 
        ? new Signature(config('services.uploadcare.private_key')) 
        : null;

    return [
        'publicKey' => config('services.uploadcare.public_key'),
        'signature' => optional($signature)->getSignature(),
        'expire' => optional(optional($signature)->getExpire())->getTimestamp(),
    ];
}
```

**签名用途**：
- 用于前端Uploadcare组件的安全上传
- 包含公钥、签名和过期时间
- 使用 `Uploadcare\Security\Signature` 类生成

private function getFileFromUploadcare(): void
{
    $configuration = Configuration::create(
        config('services.uploadcare.public_key'),
        config('services.uploadcare.private_key')
    );
    $this->api = new Api($configuration);

    try {
        $this->fileInUploadcare = $this->api->file()->fileInfo($this->file->uuid);
    } catch (HttpException $e) {
        throw new BadRequestHttpException($e->getMessage());
    }
}

## 8. 完整生命周期流程图

### 8.1 文件上传流程

```
前端上传文件到Uploadcare
        ↓
Uploadcare返回文件元数据(uuid, url等)
        ↓
前端调用后端API (document/photo/avatar store)
        ├─→ ContactModuleDocumentController
        ├─→ ContactModulePhotoController
        └─→ ModuleAvatarController
        ↓
构造上传数据，设置type (DOCUMENT/PHOTO/AVATAR)
        ↓
调用 UploadFile::execute()
        ├─→ 验证Uploadcare配置 (public/private key)
        ├─→ 验证权限 (BaseService)
        │   ├─ author_must_belong_to_account
        │   ├─ vault_must_belong_to_account
        │   └─ author_must_be_vault_editor
        └─→ 创建File模型记录
        ↓
关联文件到联系人
        ├─→ 文档/照片: $contact->files()->save($file)
        └─→ 头像: UpdatePhotoAsAvatar服务
            ├─→ 删除旧头像File记录(触发事件)
            ├─→ 更新contact.file_id
            ├─→ $contact->files()->save($file)
            └─→ 更新last_updated_at
        ↓
返回格式化后的文件DTO
```

### 8.2 文件展示流程

```
页面加载 (联系人详情 / Vault文件管理)
        ↓
ViewHelper::data() 被调用
        ├─→ 按类型查询关联文件
        │   ├─ 文档: WHERE type = 'document'
        │   ├─ 照片: WHERE type = 'photo'
        │   └─→ 头像: WHERE type = 'avatar'
        ├─→ StorageHelper::uploadcare() 获取上传配置
        ├─→ StorageHelper::canUploadFile() 检查存储限制
        └─→ 遍历文件调用 dto() 格式化
            ├─→ 文件元数据 (name, size, mime_type)
            ├─→ 下载URL (cdn_url)
            ├─→ 照片额外: 处理后的display URL
            └─→ 删除URL (destroy route)
        ↓
返回给前端渲染
```

### 8.3 文件删除流程

```
用户点击删除按钮
        ↓
调用删除API (contact级别 / vault级别)
        ├─→ ContactModuleDocumentController::destroy
        ├─→ ContactModulePhotoController::destroy
        ├─→ ModuleAvatarController::destroy → DestroyAvatar
        └─→ VaultFileController::destroy
        ↓
调用 DestroyFile::execute()
        ├─→ 验证权限 (BaseService)
        ├─→ 归属检查: $vault->files()->findOrFail($file_id)
        ├─→ $file->delete() 触发FileDeleted事件
        └─→ updateLastEditedDate()
            └─→ IF fileable_type == Contact: 更新ufileable.last_updated_at
        ↓
File模型deleted事件 → FileDeleted事件
        ↓
DeleteFileInStorage 监听器处理
        ├─→ 验证Uploadcare配置
        ├─→ 使用uuid从Uploadcare获取文件信息
        └─→ 调用Uploadcare API删除远端文件
        ↓
返回删除成功响应
```

## 总结

联系人文件生命周期设计体现了以下架构特点：

1. **关注点分离**：上传、展示、删除各阶段由专门的控制器和服务处理
2. **事件驱动架构**：通过File模型的 `deleted` 事件实现本地和远端删除的解耦
3. **统一权限模型**：所有服务继承BaseService，复用相同的权限验证逻辑
4. **安全的归属检查**：通过vault关联查询而非直接查询File，确保数据隔离
5. **多态关联设计**：File通过morphTo支持关联多种模型（目前是Contact）
6. **CDN集成**：充分利用Uploadcare的CDN能力提供图片处理和优化
7. **统一销毁入口**：DestroyFile服务被联系人级别和Vault级别删除操作共用

所有代码引用均指向实际文件，方便进一步查阅和验证。
